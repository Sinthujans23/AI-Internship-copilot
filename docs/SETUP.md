# Setup and environment reference

Use Node 22 and Python 3.13. Install with `npm ci`; create an isolated Python environment with `python -m venv matching-service/.venv`, then `matching-service/.venv/Scripts/python -m pip install -r matching-service/requirements.txt` (use `.venv/bin/python` on Linux). Do not use `--system-site-packages` for a new environment.

`npm run setup:env` creates local env files without printing secrets. Add credentials in your editor; do not paste them into chat or git. Root `.env.example` and `matching-service/.env.example` are templates only. Restart services after changes.

| Variable | Where | Visibility/purpose |
| --- | --- | --- |
| NEXT_PUBLIC_SUPABASE_URL | Next.js | Public project URL |
| NEXT_PUBLIC_SUPABASE_ANON_KEY | Next.js | Public publishable/anon key only; never service_role or secret key |
| AI_PROVIDER | Both services | `openrouter` or `openai` |
| OPENROUTER_API_KEY | Both, when selected | Private provider key |
| OPENROUTER_MODEL | Next.js | Chat model supporting structured outputs and tools |
| OPENROUTER_EMBEDDING_MODEL | FastAPI | Compatible embedding model; changing it requires regenerated embeddings |
| OPENAI_API_KEY | Both, only for OpenAI mode | Private provider key |
| OPENAI_MODEL | Next.js | OpenAI chat model |
| EMBEDDING_MODEL | FastAPI | OpenAI embedding model |
| MATCHING_SERVICE_URL | Next.js | Local HTTP service or production Render HTTPS origin |
| MATCHING_SERVICE_API_KEY | Both | Same long random private shared secret |
| MATCH_THRESHOLD | FastAPI | Skill similarity threshold, initially 0.65 |
| GITHUB_TOKEN | Next.js, optional | Private token for public GitHub API allowance |
| E2E_EMAIL / E2E_PASSWORD | Test process only, optional | Dedicated confirmed test account; never NEXT_PUBLIC_ |

No service-role key is needed by application code. The prebuild check rejects known private Supabase keys in public variables. Client-build scanning compares configured private key values without printing them.

In Supabase SQL Editor, new installations run `supabase/setup.sql`, generated by `npm run sql`. Existing installations apply missing supported migrations in order. Do not blindly run the obsolete `20261020000000_initial_schema.sql`; it predates the supported baseline. Keep backups before any production schema work.

Configure email/password authentication, production SMTP for reliable confirmation, the correct Site URL and exact `/api/auth/callback` redirects. Local callbacks must point to the computer where the app is running. Confirm your email before login. Never put a username/password in place of Supabase project credentials.

Run `npm run dev` and `npm run dev:matching` separately. `/api/health` and FastAPI `/health` are liveness checks, not provider or database billing checks.
